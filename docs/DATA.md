# SeeON 연구용 데이터 사전 (Data Dictionary)

버전 `v:2` · 앱 버전 `2026.10` · 2026-10 작성

SeeON은 게임을 한 판 마칠 때마다 기존 기록(`seeon_records`)의 `m` 칸 안에 **연구용 판 요약 `m.d`** 를 함께 저장합니다.
이름·이메일·얼굴 영상 같은 개인 식별 정보는 들어가지 않습니다. 계정과 기록을 잇는 것은 기존 `user_id`·`profile_id`뿐이며,
연구용으로 내보낼 때에는 이 둘을 가명 ID로 바꿔야 합니다(4~5단계에서 관리자 내보내기로 만들 예정).

- **연구에 쓸 수 있는 기록**: 보호자가 `research` 동의(선택)를 켠 계정의 기록만 해당됩니다.
  가장 최근 `seeon_consents` 행(`kind='research'`)의 `agreed`가 `true`이면 동의 상태입니다. 동의/철회 시각은 행마다 남습니다.
- **비회원(체험) 기록**: 기기에만 저장되며 서버로 오지 않으므로 연구 대상이 아닙니다.
- **기기 저장 공간**: 기기에 저장된 기록이 3MB를 넘으면 오래된 판의 `m.d`부터 비웁니다(계정에 올라간 기록은 그대로입니다).

조회 예시 (Supabase SQL):

```sql
-- 연구 동의 계정의 기록만, 판 요약과 함께
with c as (
  select distinct on (user_id) user_id, agreed
  from seeon_consents where kind = 'research'
  order by user_id, created_at desc, id desc)
select r.user_id, r.profile_id, r.game_key, r.stage, r.stars, r.dur, r.played_at, r.m->'d' as d
from seeon_records r join c on c.user_id = r.user_id and c.agreed
where r.m ? 'd';
```

## 1. 공통 필드 (모든 게임)

| 필드 | 형식 | 단위·값 | 설명 |
|---|---|---|---|
| `v` | 정수 | 2 | 판 요약 형식 버전 |
| `g` | 문자 | 게임 키 | 아래 2장 표의 키 (예: `meteor`, `starcode.0`) |
| `t0` | 정수 | ms (Unix) | 판 시작 시각 (종료 시각 − 플레이 시간) |
| `st` | 정수 | 1~7 | 이번 판 단계 (새 1~5단계 체계 기준). 자유 훈련 게임은 고른 단계, 없으면 생략 |
| `mx` | 정수 | 5 또는 7 | 그 게임의 최고 단계 |
| `chg` | 정수 | −6~+6 | 바로 앞 판과 비교한 단계 변화 (+ 상승, 0 유지, − 하락) |
| `att` | 정수 | 회 | 이 단계 몇 번째 도전인지 (이번 판 포함) |
| `unl` | 1 | — | 이번 판으로 다음 단계가 처음 열렸으면 1 |
| `day` | 정수 | 회 | 오늘 이 게임 몇 번째 판인지 |
| `n` | 수 | 시행 | 시행(문제·목표) 수 |
| `ok` | 수 | 시행 | 맞힘 수 |
| `ng` | 수 | 시행 | 틀림(오반응) 수 |
| `miss` | 수 | 시행 | 놓침(무반응·시간 초과) 수 |
| `acc` | 수 | 0~1 | 정확도 (`ok/n`, 게임에 따라 별도 정의 — 2장 참고) |
| `sc`, `scU` | 수, 문자 | — | 게임 대표 점수와 단위 (예: `12.3`, `"초"`) |
| `stars` | 정수 | 1~3 | 받은 별 (단계 게임만) |
| `rt` | 객체 | ms | 반응시간 요약 `{n, mean, med, min, max, sd}` — 맞힌 시행만, 0 이하 제외 |
| `cfg` | 객체 | — | 이번 판의 난이도 설정값 (게임별, 2장) |
| `gx` | 객체 | — | 게임별 추가 지표 (2장) |
| `env` | 객체 | — | 플레이 환경 (아래) |

`env` 플레이 환경:

| 필드 | 값 | 설명 |
|---|---|---|
| `sw`, `sh` | px | 기기 화면 크기 |
| `vw`, `vh` | px | 브라우저 창 크기 |
| `dpr` | 수 | 화소 배율 (devicePixelRatio) |
| `dev` | `phone` / `tablet` / `pc` | 화면 짧은 변 600px 미만이면 phone, 터치 기기면 tablet |
| `inp` | `touch` / `mouse` | 주 입력 방식 |
| `ori` | `land` / `port` | 가로/세로 |
| `cam` | 0 / 1 | 📷 눈 측정이 켜져 있었는지 (영상은 저장하지 않음) |
| `ver` | 문자 | 앱 버전 (`2026.10`) |

`gx.lr` 왼쪽·오른쪽 비교 (여러 게임 공통 형식): `{L:{n, ok, rt}, R:{n, ok, rt}}` — 목표가 화면 가로 절반 기준 왼쪽(L)·오른쪽(R)에 있었던 시행 수, 맞힘 수, 평균 반응시간(ms).

기록의 다른 칸(기존): `stage`(저장 당시 단계 번호, 예전 기록은 `m`의 표식이 없으면 옛 단계 번호), `stars`, `dur`(초), `xp`, `played_at`, `metrics`(화면에 보인 결과 카드 글자), `m`의 기존 숫자 지표, 📷 눈 측정 동의 시 `m.e_*`.

## 3. 해석 시 주의

- 단계 번호는 **2026-09 개편된 1~5단계 체계** 기준입니다(`st`). 개편 전 기록의 `stage` 칸은 옛 번호일 수 있으며, `m`에 새 체계 표식이 없으면 옛 번호입니다.
- 반응시간은 화면 갱신 주기(약 16ms)와 기기 입력 지연의 영향을 받습니다. 기기 간 비교 시 `env.dev`·`env.inp`로 나눠 보세요.
- 이 데이터는 훈련 기록이며 **의료 진단 자료가 아닙니다.** 연구에 쓸 때는 기관 IRB 심의와 가명처리 절차를 거쳐 주세요.

## 4. 관리자 화면에서 내려받기 (게임 분석 탭 → 📥 내려받기)

서버에 `supabase/research_export.sql`을 한 번 실행해야 연구용 자료를 받을 수 있어요.

**게임 분석 요약 CSV** (`seeon_game_summary_<기간>d_<날짜>.csv`) — 한 줄이 하나의 집계값인 긴 형식이에요.
`구분`(게임 / 단계 / 주) · 게임 키 · 게임 · 기간 · 단계 · 주(월요일) · 플레이 수 · 사용자 수 · 평균 별 · 별 3개 비율 · 한 판 평균(분) · 최고 단계 · 대표 지표 · 지표 중앙값 · 단위 · 좋은 방향.
모든 회원의 기록을 집계한 숫자라 개인을 알아볼 수 없어요. 단계 칸은 서버에 저장된 단계 번호예요(2026-09 개편 전 기록은 옛 번호가 섞여 있어요).

**연구용 판 단위 자료 CSV** (`seeon_research_<시작>_<끝>[_게임].csv`) — 연구 활용 동의 계정의 한 판 = 한 줄.

| 칸 | 설명 |
|---|---|
| `uid`, `pid` | 계정·조종사 가명 ID (`U`/`C` + 12자리). 서버 비밀값으로 만든 해시라 원래 ID로 되돌릴 수 없고, 언제 받아도 같은 사람은 같은 값이에요 |
| `game`, `game_name` | 게임 키(번쩍 순간포착은 `starcode.0` 숫자 / `starcode.1` 단어)와 이름 |
| `played_at_kst`, `weekday`, `hour` | 끝난 시각(한국 시간), 요일, 시 |
| `stage_saved`, `stars`, `dur_s` | 저장된 단계 번호, 별, 플레이 시간(초) |
| `has_d` | 판 요약(`m.d`)이 있는 판이면 1 (2026-10 이전 기록은 0) |
| `v` … `rt_sd`, `env_*` | 1장 공통 필드 (`stars_d`=판 요약 안의 별, `rt_*`=반응시간 요약 ms) |
| `cfg_*`, `gx_*` | 2장 게임별 변수. 안쪽 객체는 `_`로 이어 붙여요(예: `gx_lr_L_rt`, `gx_stroop_incong_acc`). 목록은 `|`로 이어 붙여요(예: `gx_ns`=`3|5|4`, `gx_dir_U`=`맞힘|수`) |
| `m_*` | 예전부터 있던 게임별 요약 숫자 (`m_acc`, `m_rt`, 📷 눈 측정 동의 시 `m_e_*` 등) |

게임마다 칸이 달라서 "모든 게임"으로 받으면 칸이 100개가 넘을 수 있어요. 분석할 때는 게임을 하나씩 골라 받는 걸 권해요.
한 번에 최대 200,000판까지 받아요(넘으면 기간을 나눠 주세요). 동의 상태는 내려받는 시점 기준이며, 동의를 끈 계정은 바로 빠져요.
